# pathology-fusion-AI

Predict the histologic growth pattern of lung adenocarcinoma (7 classes) from whole-slide
images by **fusing three pathology foundation models** (UNI2-h, Virchow2, Phikon-v2) with
patient age and sex. An **agent** searches the fusion strategy on development data only,
and every comparison row is trained with one shared MIL recipe and evaluated once on a
held-out, patient-level test split.

Dataset: [`kmmuleelab/Lung_Pathology_Image_JPG`](https://huggingface.co/datasets/kmmuleelab/Lung_Pathology_Image_JPG) (CLWD, CC-BY-4.0).

## Setup

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt          # pinned; CPU-capable stages, tests, agent, evaluation
pip install -r requirements-extract.txt  # + timm/transformers/pyvips for stage 1
pip install -e .                         # optional; scripts also work without installing
pytest                                   # 65 tests on synthetic features, ~10 min on CPU
```

Secrets are only ever read from the environment: `HF_TOKEN` (gated UNI2-h / Virchow2),
`WANDB_API_KEY` (optional curves), and an LLM key only if you choose an API backend.
Nothing secret is stored in the repo.

Every setting lives in `conf/default.yaml`. Override any key from the CLI with dotted syntax:

```bash
python scripts/02_run_agent.py agent.budget=16 agent.proposer=deterministic seed=1
```

## Design summary

**Data.** 203 usable patients, each with exactly one slide (6 patients have no slide in the
HF release). ID 8377886 is treated as one patient. For patients with conflicting labels, the
label of the imaged slide is used. The split is 140 / 22 / 41, stratified, patient-level,
checksummed, and every class appears in every partition. See `docs/DATA_DECISIONS.md`.

**Tiling.** Each 80x JPEG is decoded straight at 20x using JPEG shrink-on-load, so the full
image never sits in memory. Tissue is found with HSV saturation + Otsu at 1.25x, with pen
ink filtered out. Tiles are 224 px at stride 224, kept if ≥ 50% tissue, capped at 4096 per
slide by a seeded sample. All three models embed the *same* tiles. QC overlays are written
for every slide.

**Encoders.** Each model's preprocessing comes from its own published config:
- **UNI2-h**: 1536-d CLS token.
- **Virchow2**: 2560-d (CLS concatenated with the mean of the patch tokens, excluding 4 register tokens).
- **Phikon-v2**: 1024-d CLS token.

Normalisation runs on the GPU, from uint8 tiles. Each slide is streamed through one pass
(download → decode → tile → 3 encoders → delete), so the ~218 GB download needs disk for
only about two slides at a time. Interrupted runs resume, and work can be sharded across
sessions.

**Tile → slide aggregation.** Gated attention MIL (ABMIL) on all three models. UNI2-h,
Virchow2 and Phikon-v2 are all tile encoders, so one MIL aggregator keeps the comparison
fair. It also avoids Prism2, whose slide encoder consumes Virchow tile features and would
count Virchow twice.

**Fusion search space** (registered in `fusion/pipelines.py`):
- **Early fusion:** per-tile concatenation, with no normalisation, L2, or z-score, and optional per-model PCA to 64, 128 or 256 dims.
- **Late fusion:** one ABMIL per model, combined by probability mean, logit mean, a weighted vote fitted on out-of-fold predictions, or stacking (logistic regression on out-of-fold log-probabilities plus metadata).
- **Intermediate fusion:** a multi-stream ABMIL whose slide embeddings are fused by a learned gate, attention over stream tokens, or concatenation, with optional modality dropout.
- **Common to all three:** any subset of at least 2 models; age and sex always enter.

**Agent** (`agent/loop.py`):
1. Score the 3 single-model + metadata references. The best one is the bar to beat.
2. Run 8 *coverage* trials that span the space.
3. Adapt: a proposer reads the full trial table and picks the next config, with a reason that goes into the log.
   - Default proposer: a local **Qwen2.5-7B-Instruct** on the Kaggle GPU (free, no key).
   - Alternative: any OpenAI-compatible endpoint.
   - Without either, it falls back automatically to a deterministic hill-climber.
   - Invalid or duplicate LLM proposals are rejected and retried, then the deterministic proposer is used.

Defences against overfitting the validation data:
- Selection uses 5-fold CV on the 162 development patients; neither the 22-patient val split alone nor the test set is used.
- Budget: 24 trials.
- A trial is accepted only if its fold-paired gain is above 1 × the *Nadeau–Bengio corrected* SE.
- The search stops after 8 trials without an accepted improvement.
- The final pick uses the one-standard-error rule (the least complex config within 1 SE of the best).
- A bootstrap estimates the *winner's-curse optimism* of the best CV score.

Everything goes to `decisions.jsonl` / `decisions.md`.

**Equal-budget control.** The best-single-model row is tuned by the *same* agent with the
*same* trial budget and one-SE rule, over its own knobs (which model, normalisation, PCA)
(`SearchSpace(mode="single")`). A fused-vs-single gain therefore can't come from extra tuning.

**Known risk: acquisition-order shortcut.** Slide IDs are grouped by subtype, and the ID number
alone predicts subtype with development-CV macro AUROC 0.78 (age + sex: 0.59). If staining or
scanning batches follow ID order, image features could encode batch. `scripts/07_batch_probe.py`
tests this. `tiling.stain_normalization: macenko` (per-slide Macenko fit, applied to every tile
before encoding) is the built-in mitigation.

**Evaluation** (`eval/final.py`):
- Rows: metadata only; each model alone; best single + metadata (chosen by CV); fused + metadata (chosen by the agent).
- Every row uses the same recipe and the same 5 seeds, and is trained on train with validation curves logged to wandb (and CSV).
- Reported for each row: macro OvR AUROC (per class too) and balanced accuracy, as mean ± sd across seeds, plus the seed ensemble with a 95% stratified patient-bootstrap CI.
- Paired bootstrap differences of fused minus each row; confusion matrices; per-patient error analysis against the pathologist's `Multi_Subtypes`.
- `TEST_LOCK.json` makes test use a one-time, audited event.
